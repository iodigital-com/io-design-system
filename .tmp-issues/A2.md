## Summary
io-badge and io-input define styles inline in TSX instead of dedicated -styles.ts modules, violating component file layout conventions.

## Evidence
- io-components/src/components/io-badge/io-badge.tsx:25 injects style from class method
- io-components/src/components/io-badge/io-badge.tsx:33 defines getStyles in TSX
- io-components/src/components/io-input/io-input.tsx:93 injects style from local function
- io-components/src/components/io-input/io-input.tsx:136 defines getInputStyles in TSX
- Convention documented in AGENTS.md and CONTRIBUTING.md

## Impact
- Inconsistent architecture and review friction
- harder style-only diffing and token audits

## Proposed Fix
Extract styles to io-badge-styles.ts and io-input-styles.ts and import them from TSX.

## Acceptance Criteria
- both components use dedicated -styles.ts modules
- no local style generator function remains in TSX
- visual behavior remains unchanged

## Validation Steps
- npm run build
- npm run test

## Out of Scope
- redesigning component visuals
