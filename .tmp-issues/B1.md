## Summary
Several components include hardcoded px/rem values where token variables are expected by project styling policy.

## Evidence
- io-components/src/components/io-button/io-button-styles.ts:71,76,77,328,329,352,357,362
- io-components/src/components/io-select/io-select-styles.ts:80
- io-components/src/components/io-textarea/io-textarea-styles.ts:73
- io-components/src/components/io-carousel/io-carousel-styles.ts:48
- io-components/src/components/io-accordion/io-accordion-styles.ts:129 fallback 600px

## Impact
- style drift risk from docs/tokens source of truth
- weaker theming consistency

## Proposed Fix
Replace hardcoded literals with existing --io-* vars, and where absent, define new tokens in docs/tokens.json and app.css.

## Acceptance Criteria
- no unapproved hardcoded style literals remain in scoped files
- each replacement uses documented token variable
- governance/docs updated for any newly introduced token

## Validation Steps
- npm run build
- npm run test
- token drift review against docs/tokens.json

## Out of Scope
- broad redesign of component look and feel
