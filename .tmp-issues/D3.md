## Summary
Event test file naming is inconsistent across components (change/input/open-close naming versus required click spec convention).

## Evidence
Examples:
- io-checkbox/io-checkbox.change.spec.ts
- io-radio/io-radio.change.spec.ts
- io-select/io-select.change.spec.ts
- io-textarea/io-textarea.input.spec.ts
- io-modal/io-modal.open-close.spec.ts

Convention expects io-{name}.click.spec.ts for event emission coverage.

## Impact
- inconsistent discoverability and automation assumptions
- harder governance enforcement of test requirements

## Proposed Fix
Standardize event-emission spec naming or formally revise convention and enforce one pattern globally.

## Acceptance Criteria
- single canonical naming pattern documented
- all components conform to selected pattern
- governance validation catches naming drift

## Validation Steps
- npm run test
- governance validation after convention update

## Out of Scope
- changing test behavior semantics unrelated to naming
