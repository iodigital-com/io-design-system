## Summary
io-input generates the control id inside render using a random fallback. On rerender, this can change id linkage between label, input, and error message.

## Evidence
- io-components/src/components/io-input/io-input.tsx:88 generates io-input-${name || Math.random().toString(36).slice(2)}
- io-components/src/components/io-input/io-input.tsx:107 uses derived id in aria-describedby
- io-components/src/components/io-input/io-input.tsx:113 uses derived id in label htmlFor

## Impact
- Broken or unstable accessible name and description associations
- Flaky behavior for rerender-heavy integrations

## Proposed Fix
Generate a stable instance id once (componentWillLoad), store it on class state, and reuse in render.

## Acceptance Criteria
- id is generated once per component instance
- id remains stable across rerenders
- label htmlFor and aria-describedby remain stable and valid
- test added proving id stability across rerenders

## Validation Steps
- npm run test
- verify io-input tests include id stability case

## Out of Scope
- broader redesign of io-input API
