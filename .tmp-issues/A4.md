## Summary
io-modal uses open as both @Prop and @Event identifier. This naming collision propagates to wrappers and creates API ambiguity.

## Evidence
- io-components/src/components/io-modal/io-modal.tsx:37 @Prop() open
- io-components/src/components/io-modal/io-modal.tsx:51 @Event({ eventName: 'open' })
- wrappers mirror same ambiguity

## Impact
- confusing integration contract for state vs event
- wrapper generation edge cases and event binding ambiguity

## Proposed Fix
Rename emitted event to a non-colliding lifecycle name (for example didOpen or modalOpen) and keep migration guidance.

## Acceptance Criteria
- prop and event names are unambiguous
- wrappers regenerate cleanly
- docs/examples updated
- tests cover renamed event emission

## Validation Steps
- npm run build
- npm run test
- npm run type-check

## Out of Scope
- changing modal open state behavior
